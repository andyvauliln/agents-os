# Agent OS

The page runs from its state. `index.html` is only a runtime: it loads the newest saved version of the state, then renders `extension.views.index-view`, and everything after that comes from the state: the page html and styles (in index-view `html`) and the state editor (the code of state-view's functions).

- `state.json`: the starting state (version 1 when the page has no history yet). Saved versions may hold `//` and `/* */` comments; Save repairs common JSON slips first (`autofix` in `state-core.js`). Cmd+S / Ctrl+S saves from anywhere on the page.
- Views (`extension.views.*`): a view's `html` starts with one root element whose id is the view's name (`<header id="header-view">`); render puts it in place of the empty element with that id in the parent view's html. `html` is a template: `${...}` sees the view's `ui-data` as `d`, `e()` escapes text), then `ui-data` (everything the view shows, e.g. state-view's `current_state_version`), `functions`.
- Functions (`extension.functions.*` and a view's `local.*`): `input`, `output`, `imports` (where each import line of the code comes from: `"index.html"` for the runtime's `os` and `ctx`, script URLs, full module source, or a state path to source or URLs kept once; stylesheets are blocked on claude.ai so styles go inline), `tests`, `expected-state-change`, `docs`, `pseudo` (the code step by step in short lines with keywords SET/READ/IF/ELSE/FOR EACH/CALL/DRAW/WATCH/WAIT/RETURN/THROW, 2 spaces per level; kept in the generator's `gen/pseudo.py`, change it when the code changes), `performance` (`last`/`min`/`max`/`count` in ms), `code`, `calls`. With `code`, `code` is a module as it looks in code: import lines (`import os from 'os';`, each a key of `imports`), then `async function name({ params }) { ... }`, called with `input` (the parameters, e.g. `{ "view_path": ... }`) (older versions have no import lines and get `ctx`, `os` and `imports`; older still, a bare body); with no code, the declared `calls` run in order. `output`, `performance`, each call's `output` and each test's `result` and `errors` are filled in after every run. `errors` lists a throw and anything `expected-state-change` did not allow: `{path: "changes" | "toggles" | "input" | "same" | "may change" | value}`, `"*"` allows any change. Changes made by nested calls count for them, not for the caller, so a function that changes nothing itself has `{}`.
- A view can watch the state with `os.watch(view, fn)`: that function runs after each top-level call (state-view's `local.refresh` redraws its bar and syncs the editor this way). `os.refs` holds what can't live in the state (the editor instance, unsaved text).
- Buttons in a view's html call functions with `data-call="local.x"` (and `data-input` as JSON).
- Tests: `{ "before": {call: input}, "input": ..., "expect": { "output": {...}, "output-has": [...], "dom": [...], "dom-absent": [...], "state": {path: value}, "state-changed": [paths] } }`. The state is checked after the run.
- `state-core.js`: paths, templates, diffs, the changes view, commits, history steps, test checks and the call tracker.
- `tests/`: `node --test tests/*.test.js` (the page test needs Playwright with Chromium).
- `vendor/`: the libraries, not minified: CodeMirror 5.65.16 (`vendor/codemirror/5.65.16/`, only the files the page uses) and js-beautify 1.15.1 (`vendor/js-beautify/1.15.1/`), each with its LICENSE. The page loads them from its own files (published with the artifact), not from a CDN; the network block lists them under Packages.
- On claude.ai the page stores `commits/c000001`… (`n`, `parent`, `at`, `state`, `summary`, `paths`, and `source` for a release; a database document holds at most 256 KB, so a bigger version keeps its state in a file of the page: `state_file`, the id of an asset (the page declares the `assets` capability; served at `/_blob/<id>`), instead of `state`; without assets (not an editor) the page saves `stateGz`, the state gzipped in base64; the runtime reads both) and `calls/<session>` (each call: `name`, `input`, `output`, `ok`, `error`, `ms`, `related` with `fn`, `parent`, `stateChanges`, `performance`).

- `output` is what the function returned (JSON, runtime fields stripped); nothing returned is `{}`.
- Docs: `agents.agent-oss.files.docs` (one string per file, ASD-STE100), shown by the header's Docs button in `extension.views.docs-view`.
- The state view's viewer opens any long text (`"..."`; the pointer on it shows its start). For html, `os.preview(frame, state, viewPath, id)` runs that view in the frame with a copy of the state (the runtime and state-core run in the frame's window): its buttons work, nothing is saved, and the frame posts the view's `ui-data` and the changes after each action.
- Timeline (`extension.views.timeline-view`, rendered by state-view `local.init`; shown when state-view `ui-data.timeline_open`, the Timeline button at the left of the state view's bar): drawn from `os.calls` (the runtime's call records for this page load: `input.via` = start / click / watch / test, `related.parent` = the call it ran inside, `related.stateChanges` = what that function itself changed, before and after) and `os.started`. Not kept in the state, so drawing it never changes the state. It sits above the header: a row of blocks (`os.refs['timeline-view'].steps`; the last agent run is `.pin-left` and the newest block `.pin-right`, sticky), replay (`ui-data.playing` / `ui-data.selected`; null = the last agent run), and state-view `ui-data.track_state` (Track state: the calls of the timeline, the state view and the record button are blocks only when on). There is no step-view: the state view shows the chosen block (`os.refs['timeline-view'].current`, `number`, `versionOf`): it goes to the block's version (`os.refs['state-view'].block` / `onBlock`; Older/Newer, a draft and Save leave the block), names it in `#sv-block`, and draws in its pane `#tl-detail` Details (`drawDetails`, state-view `ui-data.details`), Changes (`drawChanges(box, kind)` for the block, `drawPair(box, kind, pairFrom(before, after, from, head))` for a version) or one kind of the state as a tree (`kindView`). Changes all = the state cut down to the changes (`stateBox`; long strings as `"..."`, `longTexts`/`preview`; the hover preview `showTip(el, text, path, before)` is a CodeMirror in the mode of the path, with the line diff of an updated text) and a table; the filter text is state-view `ui-data.filter`; a kind (state-view `filter_kind`: all / files / views / functions / network / environment) shows in `kindView` (tree of all items of that kind on the left, tabs File|View|Function|Request|Value, Pseudo code for a function (`pseudoView`), and Changes on the right; chosen item and tab in `os.refs['timeline-view'].pick`); a file shows in `fileView(name, text)` by its kind (`fileKind`): md as a page (`mdPane`, the state view's md look and `md_theme`, contents), json as a tree (`jsonPane`), code with an outline (`outlineOf`) and find/wrap/copy (`codePane`); md and json have a Source mode (`os.refs['timeline-view'].fileMode`); md Read has the six `.md-theme` buttons, which call state-view `local.set-md-theme`; Full screen (`.fv-full`, `os.refs['timeline-view'].fileFull`, Escape exits); the "..." viewer (`preview`) uses it too. Each call row in Details lists what it changed. `ui-data.show_blocks` hides the row; `ui-data.flows` = saved flows `{name, steps: [block names]}` played by `local.play-flow` (`os.refs['timeline-view'].flow`), listed when `ui-data.flows_open`.
- `network` and `environment` (top of the state): the runtime fills them (`sense()` in index.html) when each call starts and ends, so a call's `stateChanges` show what it loaded and what changed around the page; `expected-state-change` leaves them out. `network.<group>.<name>`: groups html, scripts, claude.ai (`/_runtime/` scripts of the artifact page, keyed without their hash), api (database calls), state, file code, packages, styles, other; measured `url`, `start`, `ms`, `size`, `count`, `parallel`; written by the owner: `used_for`, `expected` (true = the state lists this request; a new one gets false). `environment`: also document, window, event listeners, timers, observers, connections (index.html wraps addEventListener/removeEventListener, setTimeout/setInterval/requestAnimationFrame, the observers' observe/disconnect, WebSocket/EventSource/BroadcastChannel at the top of the runtime; `by` = the newest running call, `running`), devices, permissions (asked in `askLater()`); browser (fixed values are read once: `fixedInfo()`), browser data (storages, with `claude.ai database` from `claudeDb()`), browser api, subscriptions, background services, other. Timeline block 1 (Network) shows both, with the values of the version the page loaded.
- Agent runs: `runs/<session>-<run>.json` (in the state at `agents.agent-oss.files.runs`, as text). `scripts/run-log.js <transcript.jsonl> [--run N] [--repo . --from REV --to REV] [--version N]` prints the raw data of a run from the Claude Code session log (`~/.claude/projects/<folder>/<session>.jsonl`): `started_by`, `context` (tokens: input + cache read + cache write; cached = cache read), `uses` (mcp, skills, subagents, workflows), `events` (each tool use), `files` (read / created / updated / deleted; git wins). The `run-recorder` subagent (`.claude/agents/run-recorder.md`) turns it into the run file: no `events`, plus `title`, `steps` (`{title, lane, from, to, items, why, context_tokens, cached_tokens, files: [{path, action}]}`), and `why` on each use and file. No secrets, no file contents. The timeline (`runsOf`, `runStep`, `runDetails` in timeline-view `local.refresh`) shows the last run of the loaded state as block 1 (id `run:runs/<file>`, opens on Details; a click on a step card shows that step, `os.refs['timeline-view'].runPick`; under it tabs Changes / Reads (`runTab`; an MCP item that sends or writes is a change, other mcp/skill/subagent/workflow and run/test/search items are reads) with source buttons All / Main agent / Subagents / MCP / Skills / Workflows (`runBy`, `SOURCES`) and a tree + tabs File / Changes / Why (`runSel`, `runSelTab`); a subagent lane starts with an `.ar-branch` line and has short cards; the uses are rows of the Details `dl`), and an Agent run block after a New version block for each run that is new in it.
- State view (the one view for the state and its changes): `ui-data.filter` (text; the editor shows only paths that have it), `filter_kind` (All = the editor; Files / Views / Functions / Network / Environment = a tree in the pane, `kindView`), `changes` (Changes), `details` (Details), `timeline_open` (Timeline button), `track_state` (Track state) and `show_empty` (the Show empty box, local.toggle-empty; false hides `{}`, `[]`, `""`, `null` and texts of only `{}` or `[]` (`core.emptyText`, grey, never "...") with collapsed marks and no "⋯": state-core `filterLines(text, map, q, kind, {hideEmpty})` returns those ranges as `[from, to, 'empty']`). With Changes, an updated md file in the Files tree reads with its changes (`mdPane(text, outline, {before, why})`: `.chg-added` / `.chg-deleted` rows; the pointer shows `.why-tip`, from the run's file and step `why`, `whyOf`). The bar: Timeline button, kind buttons, Changes and Details, filter with Show empty and Track state, collapse, save, then older / newer. local.refresh folds the other lines into "⋯ N lines" marks (`os.refs['state-view'].hide`).
- Record button (`extension.views.recorder-view`, rendered by index-view `local.init` into `<div id="recorder-view">`, fixed bottom right): one click `local.start {mode: 'audio'}`, two clicks (300 ms) video; keys Arrow Up two times (400 ms) audio, Arrow Up + Arrow Down together video, same keys or a click stop (`local.stop`); not in inputs or CodeMirror. Media (MediaRecorder, the blob, the object URL), the listeners and the select-mode frames are in `os.refs['recorder-view']`, never in the state. ui-data: `recording`, `started_at`, `selected`, `selections` [{at, path}], `result` {kind, time, size, type}, `error`. The header has `#rec-timer` (drawn every 250 ms while it records). Select mode: capture listeners stop the page's clicks; `local.select {path}` (path = view state path › css path from the view, + timeline block). `local.save` uses the `downloads` capability (declared on the artifact), else an `<a download>`. Its calls are timeline blocks only with Track state on. Holding the button 4 s calls `local.open-notes` (renders `extension.views.notes-view`, a full page, empty for now; its `local.close` unmounts it); the click after the hold does nothing (`os.refs['recorder-view'].held`). Tests fake getUserMedia/getDisplayMedia (`fakeMedia`).

## Releases
`agents.agent-oss.files` is always the files of main (every file of the repo except `state.json`, which is the state; a folder with only `.gitkeep` is `{}`). The docs live in `docs/` and in `agents.agent-oss.files.docs`.

`state.json` is made by `gen/make_state.py` (views, functions and tests; `gen/docs_part.py` writes `docs/`, `gen/pseudo.py` has the pseudo code, `gen/style_part.py` the styles). Change the generator, not `state.json`, then run `python3 gen/make_state.py` and `node --test tests/*.test.js`. `node gen/build.js <previous commit.json> <release.json> <out dir>` makes the next `commits/cNNNNNN` document (release.json: `request`, `session`, `explain`). A big version also gets `cNNNNNN.state.json`: upload it as an asset of the page (Artifact publish with `asset: true`), run `node gen/build.js --state-file <out dir>/cNNNNNN.json <asset id>`, then save the document. Publish the runtime files (index.html, state-core.js, vendor/) before the document.

When a Claude Code session changes files:
1. Put the files of main into the state (`agents.agent-oss.files`) and run the tests.
2. Commit to main and push.
3. Record the run: run the `run-recorder` subagent (or do its steps) with `--from` the commit before the run and `--to` the new commit. Commit `runs/<session>-<run>.json`, put the files into the state again, and commit.
4. Save the new version as `commits/cNNNNNN` with `source`: `git` (commit hash), `branch` (`main`), `message`, `request` (the owner's words that asked for it), `session` (link), `explain` (`[{part, before, now}]`, in ASD-STE100: how each part worked before and how it works now).
5. An open page runs the new version at once (`loadNewerVersion`, input `{head, from}`); each view keeps its ui-data. The timeline's New version block shows the state changes between `from` and `head`, and in Details the source, `explain` side by side, and each changed file side by side.
