# Agent OS

The page runs from its state. `index.html` is only a runtime: it loads the newest saved version of the state, then renders `extension.views.index-view`, and everything after that comes from the state: the page html and styles (in index-view `html`) and the state editor (the code of state-view's functions).

- `state.json`: the starting state (version 1 when the page has no history yet). Saved versions may hold `//` and `/* */` comments; Save repairs common JSON slips first (`autofix` in `state-core.js`). Cmd+S / Ctrl+S saves from anywhere on the page.
- Views (`extension.views.*`): a view's `html` starts with one root element whose id is the view's name (`<header id="header-view">`); render puts it in place of the empty element with that id in the parent view's html. `html` is a template: `${...}` sees the view's `ui-data` as `d`, `e()` escapes text), then `ui-data` (everything the view shows, e.g. state-view's `current_state_version`), `functions`.
- Functions (`extension.functions.*` and a view's `local.*`): `input`, `output`, `imports` (where each import line of the code comes from: `"index.html"` for the runtime's `os` and `ctx`, script URLs, full module source, or a state path to source or URLs kept once; stylesheets are blocked on claude.ai so styles go inline), `tests`, `expected-state-change`, `docs`, `performance` (`last`/`min`/`max`/`count` in ms), `code`, `calls`. With `code`, `code` is a module as it looks in code: import lines (`import os from 'os';`, each a key of `imports`), then `async function name({ params }) { ... }`, called with `input` (the parameters, e.g. `{ "view_path": ... }`) (older versions have no import lines and get `ctx`, `os` and `imports`; older still, a bare body); with no code, the declared `calls` run in order. `output`, `performance`, each call's `output` and each test's `result` and `errors` are filled in after every run. `errors` lists a throw and anything `expected-state-change` did not allow: `{path: "changes" | "toggles" | "input" | "same" | "may change" | value}`, `"*"` allows any change. Changes made by nested calls count for them, not for the caller, so a function that changes nothing itself has `{}`.
- A view can watch the state with `os.watch(view, fn)`: that function runs after each top-level call (state-view's `local.refresh` redraws its bar and syncs the editor this way). `os.refs` holds what can't live in the state (the editor instance, unsaved text).
- Buttons in a view's html call functions with `data-call="local.x"` (and `data-input` as JSON).
- Tests: `{ "before": {call: input}, "input": ..., "expect": { "output": {...}, "output-has": [...], "dom": [...], "dom-absent": [...], "state": {path: value}, "state-changed": [paths] } }`. The state is checked after the run.
- `state-core.js`: paths, templates, diffs, the changes view, commits, history steps, test checks and the call tracker.
- `tests/`: `node --test tests/*.test.js` (set `CM_DIR` to a local codemirror@5.65.16 package to run the page test offline).
- On claude.ai the page stores `commits/c000001`… (`n`, `parent`, `at`, `state`, `summary`, `paths`) and `calls/<session>` (each call: `name`, `input`, `output`, `ok`, `error`, `ms`, `related` with `fn`, `parent`, `stateChanges`, `performance`).

- `output` is what the function returned (JSON, runtime fields stripped); nothing returned is `{}`.
- Docs: `agents.agent-oss.files.docs` (one string per file, ASD-STE100), shown by the header's Docs button in `extension.views.docs-view`.
- The state view's viewer opens any long text (`"..."`; the pointer on it shows its start). For html, `os.preview(frame, state, viewPath, id)` runs that view in the frame with a copy of the state (the runtime and state-core run in the frame's window): its buttons work, nothing is saved, and the frame posts the view's `ui-data` and the changes after each action.
- Timeline (`extension.views.timeline-view`, header Timeline button): drawn from `os.calls` (the runtime's call records for this page load: `input.via` = start / click / watch / test, `related.parent` = the call it ran inside, `related.stateChanges` = what that function itself changed, before and after) and `os.started`. Not kept in the state, so drawing it never changes the state. It sits above the header: a row of blocks (`os.refs['timeline-view'].steps`), replay (`ui-data.playing` / `ui-data.selected`), and `ui-data.track_timeline` (the timeline's own calls, and step-view's, are blocks only when on). The chosen block shows in `extension.views.step-view` under the header: tabs State changes / Details (`step-view.ui-data.tab`), drawn with `os.refs['timeline-view'].current/drawChanges/drawDetails`. `ui-data.show_changes` shows or hides the changes.
- State view filter: `ui-data.filter`, `filter_kinds` (files / views / functions) and `filter_items` (the list shown, up to 60); `local.reveal({path})` goes to an entry in the editor.
