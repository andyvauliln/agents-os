# Agent OS

The page runs from its state. `index.html` is only a runtime: it loads the newest saved version of the state, then renders `extension.views.index-view`, and everything after that comes from the state: the page html and styles (in index-view `html`) and the state editor (the code of state-view's functions).

- `state.json`: the starting state (version 1 when the page has no history yet). Saved versions may hold `//` and `/* */` comments; Save repairs common JSON slips first (`autofix` in `state-core.js`). Cmd+S / Ctrl+S saves from anywhere on the page.
- Views (`extension.views.*`): a view's `html` starts with one root element whose id is the view's name (`<header id="header-view">`); render puts it in place of the empty element with that id in the parent view's html. `html` is a template: `${...}` sees the view's `ui-data` as `d`, `e()` escapes text), then `ui-data` (everything the view shows, e.g. state-view's `current_state_version`), `functions`.
- Functions (`extension.functions.*` and a view's `local.*`): `input`, `output`, `imports` (where each import line of the code comes from: `"index.html"` for the runtime's `os` and `ctx`, script URLs, full module source, or a state path to source or URLs kept once; stylesheets are blocked on claude.ai so styles go inline), `tests`, `expected-state-change`, `docs`, `performance` (`last`/`min`/`max`/`count` in ms), `code`, `calls`. With `code`, `code` is a module as it looks in code: import lines (`import os from 'os';`, each a key of `imports`), then `async function name({ params }) { ... }`, called with `input` (the parameters, e.g. `{ "view_path": ... }`) (older versions have no import lines and get `ctx`, `os` and `imports`; older still, a bare body); with no code, the declared `calls` run in order. `output`, `performance`, each call's `output` and each test's `result` and `errors` are filled in after every run. `errors` lists a throw and anything `expected-state-change` did not allow: `{path: "changes" | "toggles" | "input" | "same" | "may change" | value}`, `"*"` allows any change. Changes made by nested calls count for them, not for the caller, so a function that changes nothing itself has `{}`.
- A view can watch the state with `os.watch(view, fn)`: that function runs after each top-level call (state-view's `local.refresh` redraws its bar and syncs the editor this way). `os.refs` holds what can't live in the state (the editor instance, unsaved text).
- Buttons in a view's html call functions with `data-call="local.x"` (and `data-input` as JSON).
- Tests: `{ "before": {call: input}, "input": ..., "expect": { "output": {...}, "output-has": [...], "dom": [...], "dom-absent": [...], "state": {path: value}, "state-changed": [paths] } }`. The state is checked after the run.
- `state-core.js`: paths, templates, diffs, the changes view, commits, history steps, test checks and the call tracker.
- `tests/`: `node --test tests/*.test.js` (set `CM_DIR` to a local codemirror@5.65.16 package to run the page test offline).
- On claude.ai the page stores `commits/c000001`… (`n`, `parent`, `at`, `state`, `summary`, `paths`, and `source` for a release; a database document holds at most 256 KB, so a bigger version has `stateGz`, its state gzipped in base64, instead of `state`; the runtime unpacks it when it reads) and `calls/<session>` (each call: `name`, `input`, `output`, `ok`, `error`, `ms`, `related` with `fn`, `parent`, `stateChanges`, `performance`).

- `output` is what the function returned (JSON, runtime fields stripped); nothing returned is `{}`.
- Docs: `agents.agent-oss.files.docs` (one string per file, ASD-STE100), shown by the header's Docs button in `extension.views.docs-view`.
- The state view's viewer opens any long text (`"..."`; the pointer on it shows its start). For html, `os.preview(frame, state, viewPath, id)` runs that view in the frame with a copy of the state (the runtime and state-core run in the frame's window): its buttons work, nothing is saved, and the frame posts the view's `ui-data` and the changes after each action.
- Timeline (`extension.views.timeline-view`, header Timeline button): drawn from `os.calls` (the runtime's call records for this page load: `input.via` = start / click / watch / test, `related.parent` = the call it ran inside, `related.stateChanges` = what that function itself changed, before and after) and `os.started`. Not kept in the state, so drawing it never changes the state. It sits above the header: a row of blocks (`os.refs['timeline-view'].steps`), replay (`ui-data.playing` / `ui-data.selected`), and `ui-data.track_timeline` (the timeline's own calls, and step-view's, are blocks only when on). The chosen block shows in `extension.views.step-view` under the header: tabs State changes / Details (`step-view.ui-data.tab`); State changes is the state view's editor (long strings as `"..."` with a hover tip and a click-to-open viewer, `longTexts`/`preview`) with its filter text (`step-view.ui-data.filter`; state-core `filterLines`, `keyOverlay` are shared with the state view) and buttons `step-view.ui-data.filter_kind` (all / files / views / functions / network / environment): a kind shows in `kindView` (tree of all items of that kind on the left, tabs File|View|Function|Request|Value and Changes on the right; chosen item and tab in `os.refs['timeline-view'].pick`), drawn with `os.refs['timeline-view'].current/drawChanges/drawDetails`. `ui-data.show_changes` shows or hides the changes. A block opens on Details when it changed nothing; choosing it again (or step-view `local.close`) hides it. `ui-data.show_blocks` hides the row; `ui-data.flows` = saved flows `{name, steps: [block names]}` played by `local.play-flow` (`os.refs['timeline-view'].flow`), listed when `ui-data.flows_open`.
- `network` and `environment` (top of the state): the runtime fills them (`sense()` in index.html) when each call starts and ends, so a call's `stateChanges` show what it loaded and what changed around the page; `expected-state-change` leaves them out. `network.<group>.<name>`: groups html, scripts, claude.ai (`/_runtime/` scripts of the artifact page, keyed without their hash), api (database calls), state, file code, packages, styles, other; measured `url`, `start`, `ms`, `size`, `count`, `parallel`; written by the owner: `used_for`, `expected` (true = the state lists this request; a new one gets false). `environment`: also document, window, event listeners, timers, observers, connections (index.html wraps addEventListener/removeEventListener, setTimeout/setInterval/requestAnimationFrame, the observers' observe/disconnect, WebSocket/EventSource/BroadcastChannel at the top of the runtime; `by` = the newest running call, `running`), devices, permissions (asked in `askLater()`); browser (fixed values are read once: `fixedInfo()`), browser data (storages, with `claude.ai database` from `claudeDb()`), browser api, subscriptions, background services, other. Timeline block 1 (Network) shows both, with the values of the version the page loaded.
- Agent runs: `runs/<session>-<run>.json` (in the state at `agents.agent-oss.files.runs`, as text). `scripts/run-log.js <transcript.jsonl> [--run N] [--repo . --from REV --to REV] [--version N]` prints the raw data of a run from the Claude Code session log (`~/.claude/projects/<folder>/<session>.jsonl`): `started_by`, `context` (tokens: input + cache read + cache write; cached = cache read), `uses` (mcp, skills, subagents, workflows), `events` (each tool use), `files` (read / created / updated / deleted; git wins). The `run-recorder` subagent (`.claude/agents/run-recorder.md`) turns it into the run file: no `events`, plus `title`, `steps` (`{title, lane, from, to, items, why, context_tokens, cached_tokens, files: [{path, action}]}`), and `why` on each use and file. No secrets, no file contents. The timeline (`runsOf`, `runStep`, `runDetails` in timeline-view `local.refresh`) shows the last run of the loaded state as block 1 (id `run:runs/<file>`, opens on Details; a click on a step card shows that step and its files as a tree, `os.refs['timeline-view'].runPick`), and an Agent run block after a New version block for each run that is new in it.
- State view filter: `ui-data.filter` (text; the editor shows only paths that have it) and `filter_kinds` (switches files / views / functions; off hides them). local.refresh folds the other lines into "⋯ N lines" marks (`os.refs['state-view'].hide`).

## Releases
`agents.agent-oss.files` is always the files of main (every file of the repo except `state.json`, which is the state; a folder with only `.gitkeep` is `{}`). The docs live in `docs/` and in `agents.agent-oss.files.docs`.

When a Claude Code session changes files:
1. Put the files of main into the state (`agents.agent-oss.files`) and run the tests.
2. Commit to main and push.
3. Record the run: run the `run-recorder` subagent (or do its steps) with `--from` the commit before the run and `--to` the new commit. Commit `runs/<session>-<run>.json`, put the files into the state again, and commit.
4. Save the new version as `commits/cNNNNNN` with `source`: `git` (commit hash), `branch` (`main`), `message`, `request` (the owner's words that asked for it), `session` (link), `explain` (`[{part, before, now}]`, in ASD-STE100: how each part worked before and how it works now).
5. An open page runs the new version at once (`loadNewerVersion`, input `{head, from}`); each view keeps its ui-data. The timeline's New version block shows the state changes between `from` and `head`, and in Details the source, `explain` side by side, and each changed file side by side.
