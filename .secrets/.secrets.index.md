# .secrets/

## What it is

The single store for every private key, wallet key, API key and token. It sits at the top of the repository, outside `agents/`, so no agent session has it in its folder. The folder, `secrets.index.json` and all the metadata files are in git; only the `.env` files that hold values are git-ignored and stay on the machine. It holds `test/` with the test keys, `live/` with the live keys that only the owner writes, and `secrets.index.json`, the list of key names with no values, empty for now. Scripts are meant to get keys only through `load-secret`, a planned shared script, at run time and only the names their config lists.

## Who looks after it

It is written by the owner.

## When and how it changes

It changes when a keys file or the key index is added or removed, or the rules for keys change.

## Who uses it, and when

It is read by the owner; load-secret (the proposed shared loader, not written yet); and every agent, for key names only.

## Where it is mentioned

It is described in `docs/README.md`, `agents/system/docs/README.md`, `docs/rebuild-prompt.md` and its folder's How it works file `agent-os.index.md`.

## Related knowledge

It is checked by `.gitignore`. The rules that apply to it come from `agents/system/CLAUDE.md` (section "Rules"), `docs/metadata.md`, `docs/README.md` (section "Keys and secrets") and `agents/system/docs/README.md` (section "Keys and secrets").

## Keep in mind

- When anything needs a secret, go through `load-secret` and `secret_keys`; never put a value in a config, doc, log, prompt or link.
- When you touch `live/`, stop: only the owner does that.
