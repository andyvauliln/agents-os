# .env

## What it is

The live twin of the test `.env`: it is meant to hold the same sections and key names with live values. An empty file exists on the machine; it is git-ignored, so it is never in git, and the page lists it as local-only without its text. Only the owner writes it, in a later phase; no agent reads, writes or switches itself to it. Its key names, with no values, are in `.env.example` next to it.

## Who looks after it

It is written by the owner.

## When and how it changes

It changes when the owner adds, removes or changes a live key, when acting live begins. It is empty for now.

## Who uses it, and when

It is read by load-secret (the proposed shared loader, not written yet), only for owner-approved live runs.

## Where it is mentioned

It is described in `.secrets/secrets.index.json` and its folder's How it works file `.secrets/live/live.index.md`.

## Related knowledge

It has the same format as `.secrets/live/.env.example` and `.secrets/test/.env`. It is checked by `.gitignore`. The rules that apply to it come from `agents/system/CLAUDE.md` (section "Rules"), `docs/metadata.md`, `docs/README.md` (section "Keys and secrets") and `agents/system/docs/README.md` (section "Keys and secrets").

## Keep in mind

- When you need a live key, ask the owner; an agent never reads, writes or switches itself to this file.
