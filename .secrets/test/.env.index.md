# .env

## What it is

The file meant to hold every test credential as `KEY=value` lines, grouped in comment sections (mode, models, platforms and accounts, notifications), with names that start with their account or platform, such as `POLYMARKET_ACCT1_API_KEY`. It is git-ignored and stays on the machine; its key names, with no values, are in `.env.example` next to it. The project IDE server reads its keys from it by name. Agents and the dev workflow may read and update it, since these are safe test keys.

## Who looks after it

It is written by the owner.

## When and how it changes

It changes when a test key is added, renamed, removed or given a new value. It is empty for now.

## Who uses it, and when

It is read by load-secret (the proposed shared loader, not written yet); and scripts that list the key in secret_keys.

## Where it is mentioned

It is described in `.secrets/secrets.index.json` and its folder's How it works file `.secrets/test/test.index.md`.

## Related knowledge

It has the same format as `.secrets/test/.env.example` and `.secrets/live/.env`. It is checked by `.gitignore`. The rules that apply to it come from `agents/system/CLAUDE.md` (section "Rules"), `docs/metadata.md`, `docs/README.md` (section "Keys and secrets") and `agents/system/docs/README.md` (section "Keys and secrets").

## Keep in mind

- When you add a test key, put it in the matching section with its account or platform prefix and add the same name to `live/.env` and `secrets.index.json`.
- When a config or job needs a key, list its name in `secret_keys`; never copy the value anywhere else.
