# .claude/

## What it is

The system level's Claude Code folder, laid out the same way at every level. It holds the settings (`settings.json`, and `settings.local.json` for one machine), the skills in `skills/`, the helper agents in `agents/` (the self-improvement agent, the knowledge base agent and the project IDE agent), the sub-agents' memory folders, and `rules/`, `commands/`, `output-styles/` and `workflows/`, which hold only name patterns for now. The file Claude Code reads first, `CLAUDE.md`, is not here but one level up, in `agents/system/`; the docs for people are in the system's `docs/`.

## Who looks after it

It is written by the owner, knowledge-base-agent, project-ide-agent and change-plan.

## When and how it changes

It changes when a helper agent, a skill, a setting or one of the standard parts is added, changed or removed.

## Who uses it, and when

It is read by Claude Code started in agents/system/, knowledge-base-agent, project-ide-agent and the owner.

## Where it is mentioned

It is described in `agents/system/docs/README.md`, `agents/system/docs/rebuild-prompt.md` and its folder's How it works file `agents/system/system.index.md`.

## Related knowledge

It is read by `agents/system/CLAUDE.md`. It links to `agents/system/.claude/agents/`, `agents/system/.claude/skills/` and `agents/system/.claude/settings.json`. The rules that apply to it come from `agents/system/CLAUDE.md` (section "Rules"), `docs/metadata.md`, `agents/system/docs/README.md` (section "Each agent's AI setup") and `agents/system/docs/rebuild-prompt.md` (section "The standard .claude/ folder").

## Keep in mind

- When you need to share something from here with another level, hand it over as a data file; never link a `.claude/` folder or file.
- When you put something in `settings.local.json` or `agent-memory-local/`, remember they are meant to stay on one machine but are tracked in git today as empty placeholders.
