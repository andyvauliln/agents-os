# README.md

## What it is

The full and exact description of the `apps/` folder: every app with its kind, place and state, how the folder is laid out, each part (the apps docs, the project IDE, the prediction-market dashboard, research clones, apps we use from outside), the list of apps, and where each app's own docs are.

## Who looks after it

The knowledge base agent, with the `readme-doc` skill and its outline for an app. The owner can also change it on the File Tree page.

## When and how it changes

After every change to an app or to the rules for outside code, after the vision and before the ASD-STE100 version and the rebuild prompt. The agent rewrites the parts the change touches, checks every "Its docs" path is real, and updates the list of apps and the open points.

## Who uses it, and when

Readers after the vision, the owner after a round of changes, and every agent before it works on an app it does not know. It is where an AI finds which app lives where and where its docs are.

## Where it is mentioned

The apps vision's last section; its ASD-STE100 twin `README.asd.md`, which follows it section by section; the apps rebuild prompt; the system README's part on apps and the IDE.

## Related knowledge

The vision gives the why; the rebuild prompt gives the exact build; each app's own README goes deeper. For now it also holds the list of apps as a table, a proposal until the owner says where the list lives.

## Keep in mind

- When you change it, rewrite `README.asd.md` to match in the same change.
- When an app is added, updated from its source or removed, update its row in the list of apps.
- When you name a path, make sure it exists.
