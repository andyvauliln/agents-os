## 1. What it is
A personal "Trading OS": an agentic system running hundreds of trading agents of different types across several domains. Agents share a common base and differ by domain, strategy and configuration.

The system does five things:
- continuously collects data from many sources
- lets each agent consume only the data relevant to it
- lets agents decide and act
- improves the agents over time
- makes it cheap to run many strategy/configuration variants side by side and see which work

## 2. Core building blocks (owner's model)

### Workers (and sub-agents)
- Run periodically, as scheduled scripts or as agents; watch sources and prepare data.
- Write their output into a shared Data store.
- Examples: important-events collector, news, prices, errors, running a sub-agent.

### Data
The central store of everything workers produce.

### Strategy agents
- Each belongs to a domain and is subscribed to the data it needs. It knows which data relates to it, and how and when to get it.
- Runs periodically. On each run it takes all new data available to it since its last run.
- Owner's initial idea: the needed files are linked (symlinked) into the agent's own folder.
- Context compression is needed; exactly how is still to be worked out.

### Agent run loop
Read data → Analysis → Decision → Action. Possible decisions and actions:
- buy · sell · sell all
- wait for needed information · set a reminder / schedule the next run
- collect additional data · do research (create and run a new sub-agent)
- create / subscribe / unsubscribe / configure / schedule workers

### Agent folder (one per agent)
config · common config · docs · logs · common prompt · agent prompt · memory · self-improvement strategy · list of workers and subscriptions · trading accounts · data · previous run and next runs info · current portfolio · analytics

## 3. Requirements for every agent
- Has a self-improvement strategy. The self-improvement strategy itself can be varied and tested.
- Has a test mode; supports backtesting where the strategy allows it.
- Runs with different configurations: initial capital, risk-management strategy, personal settings, domain settings.
- Purpose: run and compare many variants, combine strategies and approaches, and keep what works.
- Common vs different: shared base behavior for all agents; domain- and strategy-specific parts on top.

## 4. Domains and strategy examples (the scope is large and varied)
- **Prediction markets:** up to ~80 distinct ways to make money. Examples: market making, analysing outcome probabilities, agents that model possible futures and simulate them.
- **Crypto / bitcoin trading:** technical trading and others.
- **Copy trading.**
- **Content-driven:** take one YouTuber, extract everything they say, and trade on it.
- **Combinations:** blend strategies, e.g. combine the ones with the best win rates.

## 5. Ideas raised earlier (NOT decided, evaluate them)
- **Strategy vs instance.** Write dozens of strategy templates and spawn hundreds of agents as configured instances (strategy version + capital + risk policy + model + mode). Experiments generate instances.
- **Pull instead of symlinks.** Agents pull via subscriptions with a per-agent read cursor, instead of files being symlinked into agent folders. Workers then don't need to know about agents, and replaying history for backtests becomes easy.
- **Agents decide, a separate layer executes.** Decisions become typed intents, which go through risk checks enforced in code, then to a live / paper / shadow / backtest executor with the same interface. Test mode becomes a config setting.
- **Ledger owns the portfolio.** A ledger is the source of truth for positions; agents see a read-only snapshot.
- **Not every strategy fits a periodic LLM loop.** Market making and arbitrage need fast, event-driven code. Strategies could be of kind code, LLM, or hybrid.
- **Self-improvement produces challengers.** An improved version is tested against the current champion before promotion, rather than an agent editing itself live.
- **Compress context upstream.** Shared digests are computed once, then each agent filters, and each run ends with a short memory note.
- **LLM backtests can leak.** A model may already know outcomes from before its training cutoff, so paper/shadow trading is the honest test for LLM strategies.
- **External text is untrusted input.** News, YouTube and social text can carry prompt injection, so hard risk limits belong in code, not in prompts.
- **Meta-agents.** Some agents take other agents' signals as input (ensembles, capital allocators).
- **Worker requests.** When an agent asks for a new worker, first check whether that data already exists; set limits so hundreds of agents don't spawn duplicate workers.
