# plans/

## Summary

One plan for every change request, written with the `change-plan` skill before anything is built, and an index of every plan with its status. A plan is the working document of one change: the owner sees it, the build follows its steps, and once it is built its knowledge moves to the files that own it and the plan goes to the archive. Today it holds four: working from two places through GitHub (agreed, waiting for the owner's GitHub project), the File Tree page on the owner's server (built), one file for every tab on the page (waiting for the owner), and the plan for plans, features, docs at every level and a general system (waiting for the owner).

## Keep in mind

- When you add a plan, add its row to the index too, and keep its status true as it moves from waiting to built to archived.
